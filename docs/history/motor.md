# 모터

> 2026-09 모터 작업의 기록. 완료 후 고정 — 이후 변경은 반영하지 않는다.

## 개요

기동 시 모터 캘리브레이션의 목표를 다시 잡은 작업이다. "자이로로 본 수평"에서 "세 와이어 모두 텐션이 잡힌
수평"으로 바꿨고, 판정 노이즈와 이동 방식을 실측으로 다듬었다(2026-09-01 ~ 09-11). 같은 달에 두 가지가 이어졌다.
- 자세 센서를 MPU6050 에서 LSM6DS3TR-C 로 교체했다(2026-09-18).
- 기기별 모터 홈 값을 공유 설정에서 기기별 `config/robot.toml` 로 분리했다(2026-09-18).

캘리브레이션이 지금 어떻게 동작하는지는 [motor-calibration.md](../motor-calibration.md)에 있다.

## 캘리브레이션 — 자이로 수평에서 "텐션이 잡힌 수평"으로 (2026-09)

### 목표와 텐션의 정의

- **의도 재확인**: 캘리브레이션의 목표는 수평 + 세 와이어 모두 텐션이다.
  - 기존 코드는 수평(절대 문턱)만 봤다. 텐션은 roll 에만 오버슈트(0.15 g)로 우연히 보장됐다.
  - pitch 는 `Ay > 0.009` 절대 문턱과 `int now_Ay = Ay`(소수 절단 → 항상 0) 때문에 실기기에서 3틱만 감고 끝났다
    (이완 3726 → 홈 3723, 2026-09-04). "pitch 가 풀린 채 시작하면 안 당겨진다"는 관찰의 원인이 이것이었다.
- **텐션 = "감았을 때 수평 너머로 움직였다"**:
  - 감아도 값이 안 변하면 슬랙, 변하면 팽팽하다.
  - 문턱(`calib_tension_g`, 0.05 g ≈ 2.9°)만큼 수평을 지나친 뒤 반대 줄로 수평까지 되당기면, 길항 구조라 양쪽이
    팽팽해진다.
  - roll 은 원래 이 구조였고, pitch 에도 같은 트릭을 적용했다(pitch 오버슈트 → roll 둘로 되세우기).
  - 문턱은 노이즈 바로 위가 정답이다. **오버슈트 각도가 곧 최종 당김량(압축)** 이라 크면 과압축, 작으면 노이즈에
    걸려 조기 탈출한다.

### 당김량과 문턱

- **당김량 = 되세우기 이동량이라 목표는 수평 기준**:
  - 처음엔 목표를 "시작 Ay + 0.05"로 잡았다. 그런데 roll 오버슈트를 0.15 → 0.05로 줄이자, 머리가 앞으로 처진
    채(Ay 0.11) pitch 를 시작해 되세우기가 0.15 g, 즉 당김량 3배로 튀었다.
  - 그래서 목표를 "수평(0.009) + 0.05" 절대값으로 고정하고, 머리가 앞이면 roll 둘로 수평까지 먼저 되당긴다.
  - 이러면 당김량이 roll 감김 양과 무관하게 0.05로 고정된다(실측 0.053~0.064).
- **roll 오버슈트는 좌우 당김에만 영향**:
  - 0.15 → 0.05로 줄여도 최종 위치는 같았다(3426/710/2613 vs 3434/710/2618).
  - 총 roll 감김은 "수평 + pitch 당김량"이라는 기하 조건이 정하고, 오버슈트로 덜 감은 만큼은 수평 선행에서 다시 감는다.
  - 따라서 roll 오버슈트 값은 좌우로 밀었을 때의 유격으로만 판단할 것. 문턱을 roll·pitch 공용 하나
    (`calib_tension_g`)로 통일한 근거다.

### 노이즈 실측 — 문턱의 근거

- **필터 설정**: MPU6050 기본(DLPF 260 Hz)에서 정지 σ 는 3샘플 0.015 g, 10샘플 0.008 이었다. 원작성자가 "3샘플로는
  이완 판정 불가"라 적은 이유다.
  - DLPF_CFG=4(21 Hz, 지연 8.5 ms)로 3샘플 σ 0.006, 10샘플 0.003 — 3배 개선.
  - 5·6(10·5 Hz)은 10샘플 기준 개선 없이 지연만 늘어 제외했다.
  - 바이트 2회 읽기 vs 6바이트 버스트는 차이가 없었다(튐 0).
- **문턱은 동작 조건의 노이즈로**: 토크 온 + 이동 직후 노이즈는 정지보다 크다. 이완 판정 지표가 정지 최대 0.018 →
  이동 후 145 ms 마진에서 0.016, 50 ms 마진에서 0.029 였다.
- **함정**: `mpu6050_init` 이 CONFIG 를 건드리지 않아 DLPF 설정이 전원 유지 중 남는다. 그래서 매 기동 명시적으로 쓴다.
  (→ 이후 센서 교체로 DLPF 설정은 해당 없음 — 아래 센서 교체 절)

### 연속 이동 — lag 제거

- **lag 의 원인은 "goal 주기 < 프로파일 시간"**: 원 코드는 goal 을 35 ms 마다 쓰고 프로파일은 100 ms 였다. 그래서
  goal 이 실제보다 3~4스텝 앞섰고, 그 lag(0.02~0.035 g)만큼 오버슈트가 커졌다(roll 0.05 문턱에 실제 0.07~0.085).
- **대안 비교**:
  - 스텝마다 정지 후 읽기는 lag 는 없지만, 7 Hz 스톱앤고로 떨리고 140 ms/스텝이다.
  - **goal 주기 = 프로파일 시간(50 ms)** 으로 맞추면 모터가 연속으로 흐르고 lag < 1스텝이다. 부드럽고 정확하며 60 ms/스텝.
- **세부**: 이동 끝자락 30 ms 에 3샘플을 겹쳐 읽는다. roll 둘을 함께 당길 땐 머리 속도가 2배라 스텝을 절반(3틱)으로
  한다 — 6틱이면 수평을 0.026 지나쳤다.

### 폐기한 것과 이유 (모두 실측)

- **모터 위치·속도 읽기로 도달 확인**: 고정 대기와 같은 151 ms/스텝이었고 타임아웃이 30%였다. 텐션 걸린 상태에서는
  goal ±2틱에 못 들어온다.
- **pitch 빨리 감기**: 목표까지 0.05뿐이라, 이동 중 읽기 lag 가 당김량을 0.05~0.07 사이 운에 맡긴다. 머리 구조상
  토크가 풀리면 앞으로 기울어 pitch 슬랙이 원래 적고, 그 대부분은 수평 선행이 걷는다.
- **roll 마무리 수평 보정**: roll 둘 동시 150틱 스윕에서 Ax 드리프트가 없었다. 본 것은 토크 온 읽기 산포(±0.02)였다.
- **이완 세틀 마진 50 ms**: 노이즈 최대 0.029로 임계 0.03에 닿았다.

### 이완

- **이완은 "적당히"지만 없앨 수 없다**: 모든 감기 단계는 감기만 하므로 이완이 유일한 풀기다. 없으면 반복 실행마다
  조여지는 래칫이 된다.
- **순차 유지(모터 하나씩 + 라운드)**: 세 줄을 동시에 풀면, 셋이 균형 잡힌 채 팽팽한 경우 변화가 안 보일 수 있다.
- **과잉 슬랙 축소**:
  - 100틱/0.05 → 60틱/0.03 으로 줄였다(DLPF 로 가능해짐).
  - 이완 전용 프로파일은 200 ms 다. 홈 이동의 500 ms 는 수천 틱 이동용이다.
- **스텝별 Δ 로그**: 다른 기기에서 임계 여유를 바로 볼 수 있게 남긴다.

### 실기 관찰

- **토크 오프 시 roll_r 스풀이 ~400틱 되감김**:
  - 머리 무게가 팽팽한 roll 줄을 당겨 풀어버린다(pitch 는 머리가 앞으로 기울어 안 풀린다).
  - 그래서 다음 기동의 슬랙 양이 직전에 어떻게 꺼졌는지에 좌우된다.
  - 캘리브레이션 시간(22~28 s)의 산포 대부분이 여기서 온다.
- **센서 오프셋(`calib_ax_offset`)은 기기별**:
  - 장착 각도 + MPU6050 영점 편차(사양 ±50 mg)의 합이다.
  - 위치 치우침은 정적 기울기 측정에 무관하다(중력 방향은 강체 어디서나 같음).
  - unit4 값(0.036)을 mk3 에 시험 적용해 정면에서 수평을 확인한 뒤 채택했다.
- **기기별 설정 사고**: 새 기기 캘리브레이션 값이 기존 `[robot.unit4]` 를 덮어써, mk3 가 다른 기기의 yaw 홈(3560)으로
  정렬돼 88° 회전했다. 대책은 "기기별 섹션은 새로 추가하고, 홈 위치 값은 반드시 `RAY_UNIT` 과 함께 본다"였다.
  (→ 이후 `robot.toml` 분리로 대체 — 아래 절)

## 자세 센서 MPU6050 → LSM6DS3TR-C 교체 — 드라이버 계층만, 판정 로직 불변 (2026-09-18)

- **축·부호 동일 확인 후 최소 수정**:
  - 새 보드를 같은 자리에 고정하고 손 기울임 + 모터 감기(roll_r/roll_l/pitch 각각 30틱 스텝)로 실측했다.
  - roll_r 감으면 Ax+, roll_l 감으면 Ax−, pitch 감으면 Ay+, 수평 Az≈+1 g 로 기존 규약과 같았다.
  - 그래서 캘리브레이션 판정은 그대로 두고 드라이버 차이만 바꿨다: 주소(0x68→0x6A), 출력 레지스터(0x3B→0x28),
    바이트 순서(빅→리틀엔디언), 스케일(16384→16393 LSB/g).
- **WHO_AM_I 0x6A**: 순정 LSM6DS3(0x69)가 아니라 TR-C(또는 DSL)다. 레지스터 맵이 같아 코드 차이는 없다.
- **LPF2 생략**:
  - MPU6050 은 DLPF 21 Hz 를 걸어야 σ 6 mg(3샘플)였는데, 이 칩은 필터 없이 104 Hz 단일 샘플 σ 0.6 mg 다.
  - LPF2 ODR/9(≈23 Hz)는 0.5 mg 로 개선이 없다. ODR/50(≈4 Hz)은 0.2 mg 지만, 스텝 직후 읽기(50 ms)에 지연이 걸려 제외했다.
  - `calib_release_noise_g`·`calib_tension_g` 문턱은 옛 노이즈 기준이라, 여유가 커졌을 뿐 그대로 유효하다.
- **함정 — 초기화는 ODR 한 줄**: 기본이 power-down 이라 CTRL1_XL 을 켜지 않으면 출력이 0 이다. 전원 유지 중 남는
  레지스터지만 매 기동 명시한다.

## 기기별 모터 홈 값을 `robot.toml` 로 분리 (2026-09-18)

공유 config 에서 `[robot.unitN]` 과 `RAY_UNIT` 을 없앤 작업이다.

- **문제**: 기기별 값을 추적되는 `cpp/config.toml` 에 유닛 섹션으로 모아 두고 환경변수로 고르는 방식은, 기기가
  늘수록 충돌했다.
  - unit4 를 새 기기가 덮어써 mk3 가 unit5 로 밀렸다(위 기기별 설정 사고).
  - 캘리브레이션 결과는 콘솔에 찍힌 것을 손으로 옮겨 적어야 했다.
  - 다른 기기 값을 내 커밋에 실어 보내는 것도 어색하다.
- **결정**: [저장소 폴더 정리](repo-structure.md)와 같은 기준을 따른다. 운영자가 기기마다 손으로 쓰는 파일은
  `config/`(gitignore)에 둔다.
  - `config/robot.toml` 에는 `default_*` 다섯 개와 `calib_ax_offset` 만 둔다.
  - C++ 는 공유·기기별 두 파일을 읽어 합친다.
  - 기기별 파일이 없거나 키가 빠지면 이전처럼 즉시 실패한다 — 잘못된 홈으로 이동하는 것을 막기 위해서다.
- **감수**: 기기별 값이 git 에 남지 않는다. 캘리브레이션으로 재생성되는 값이라, SD 카드를 교체하면 다시 잡으면 된다.
