  2026-10-21 제거됐고, 같은 구조가 노래 재생 경로로 남았다.
- 2026-09-11 링 LED 깜박임을 진단했다(링 보드 불량).
- 2026-09-23 GPT-Live 세션에 노래 재생·정지 툴(`play_song` / `stop_song`)을 붙였다. 라이브 스트림과 C++ 파일 재생이
  교대하는 구조, 노래 중에도 사용자 말을 듣는 방법이 핵심이었다.
- 2026-09-28 곡마다 들쭉날쭉한 음원 레벨을 음원 자체에서 정규화했다.

## LED 구동과 노래 궤적 재생

- **LED 밝기 = RPi 하드웨어 PWM(sysfs), Dynamixel 과 분리**: 밝기는 RP1 하드웨어 PWM(`/sys/class/pwm/pwmchip0/pwm1`,
  GPIO13)에 duty(ns)를 써서 구동하고, 부팅 systemd 서비스(`setup_led_hwpwm.sh`)가 캐리어를 세팅한다.
  - 초기엔 WiringPi softPwm(핀 무제약, 추가 의존성 0)이었으나 ~100Hz 주파수 한계(플리커)로 하드웨어 PWM 으로 바꿨다.
  - `led_pwm_pin < 0` 이면 비활성 — 배선 전이나 다른 보드에서 임의 GPIO 를 건드리지 않게 막는다.
  - ID6 Dynamixel LED 각도 모터 구동은 없앴다 — 메인 파이프라인은 밝기 1채널만 쓴다.
- **노래 재생 = 한 프로세스·한 클럭**: 머리·입·LED 궤적은 오프라인으로 CSV 를 만들어 두고, 재생은 C++
  `csv_control_motor` 하나가 WAV 재생과 같은 시작 시각(steady_clock)에서 40ms 프레임으로 모터·LED 를 함께 구동한다.
  Python 은 `play_audio_csv` 로 곡 이름만 넘긴다. 재생 중 위치를 프로세스 간에 주고받지 않으므로 IPC 지연·지터가
  동기화에 끼어들지 않는다.
- **LED CSV 프레임 정렬**: LED CSV 는 헤드/입 CSV 와 행 수·시간축이 같다는 핸드오프 전제에 기댄다.
  `csv_control_motor` 의 SKIP_FRAMES 보간 구간에서도 LED 행을 같은 박자로 소비해 정렬을 유지한다(LED 는 보간 없이
  원본값). LED 파일이 없으면 LED 만 꺼지고 모터 1~5 는 정상 재생한다.
- **LED 밝기 신호 = HPSS 블렌드**: 단색 LED 1채널이라 밝기만 제어한다.
  - `librosa.effects.hpss` 로 하모닉(지속음 → 느린 attack/release 글로우 바닥)과 퍼커시브(트랜지언트 → fast
    attack/slow release 펀치)를 나눠 블렌드한다. 멜로디와 드럼이 섞이지 않아 박은 선명하고 무드는 매끄럽다.
  - 처리 체인: dB 스케일 → 퍼센타일 정규화(곡별 다이내믹 레인지 활용, 이상치 강건) → 비대칭 스무딩 → 감마 ~2.2
    (지각-선형 밝기) → 바닥값 ~12%(스트로브 방지).
  - 사람은 음량을 로그로, 밝기를 비선형으로 지각한다. 두 보정이 "귀로 듣는 크기 ≈ 눈으로 보는 밝기" 를 맞춘다.
  - HPSS 는 lookahead 가 필요해 오프라인 전제다. 실시간(마이크) 입력이면 재설계가 필요하다.
- **시그널 핸들러 데드락 → 워처 스레드**: csv 재생 중 Ctrl+C 가 안 듣던 버그. `signal_handler` 가 인터럽트당한
  스레드 컨텍스트에서 `dxl_mutex_` 를 잡으려다, 매 프레임 모터 write 로 뮤텍스를 쥔 메인 스레드(=자기 자신)를
  기다리는 데드락이었다. SIGTERM 도 같았고 SIGKILL 만 들었다.
  - 해결: 핸들러는 원자 플래그(`g_shutdown_requested`)만 세우고 반환하고, 별도 `shutdown_watcher` 스레드가 정상
    컨텍스트에서 LED 소등 + 토크 해제 후 `_Exit` 한다.
  - dxl_driver 는 `delete` 하지 않는다(use-after-free 경합 회피) — 토크만 끄고 OS 회수에 맡긴다.
  - 교훈: 시그널 핸들러에서 mutex/`cout`/`new`·`delete` 는 async-signal-safe 가 아니다.

## LED 링 임의 색 깜박임 — 링 보드 불량

2026-09-11 진단.

- **증상**: RAY 기동 후 링 LED 에 흰색·잡색 픽셀이 간헐적으로 튀었다. 데몬 재시작(`install.sh`) 때의 ATtiny 동시
  드라이브 깜박임과 겉보기가 같아 처음엔 그쪽으로 추적했다.
- **판별 순서와 기각**:
  1. arbiter 로그로 두 Pi 프로세스 충돌이 아님을 확인.
  2. SPI 열기·설정만 하는 프로브로 "열기 글리치" 기각.
  3. RAY·데몬을 다 끄고 Pi 가 직접 회색 프레임을 60 fps 로 쓰는 프로브에서는 깨끗했다.
  4. 그런데 **데몬이 꺼져 ATtiny 만 그리는 상태에서도 링 아래 8개만 튀었다**. 5 V 소스에서도 그랬다. 체인의 특정
     구간 이후만 깨지면 신호가 아니라 그 경계의 하드웨어다. 링 보드 교체로 해소됐다.
- **교훈 1 — 색으로 원인을 가를 수 없다**: 두 송신기가 겹쳐도 비트가 섞여 임의 색이 나온다. "임의 색 = 신호 노이즈,
  노랑 = ATtiny" 라는 구분은 틀렸다.
- **교훈 2 — 갱신 주기가 가시 시간을 정한다**: 깨진 픽셀은 다음 프레임에 덮인다. 데몬 60 fps(16 ms)·RAY 정적
  10 fps(100 ms)에선 "파박" 으로만 보이고, ATtiny IDLE(검정 1 s 재전송)에선 1초씩 남아 또렷하다. 같은 불량이
  상황마다 다르게 보였던 이유다. 펌웨어의 "IDLE 검정 재전송(유령 픽셀 방지)" 도 같은 계열의 증상을 덮던 것일 수 있다.
- **교훈 3 — 격리는 소스를 바꿔서**: Pi 가 그릴 때와 ATtiny 가 그릴 때 둘 다 재현되면 소프트웨어·레벨(3.3 V)·모터
  노이즈가 한 번에 빠진다. 인덱스 범위로 일부만 켜서 어디부터 깨지는지 찍으면 위치가 나온다.
- **부수 확인 — 부팅 시 RAY 는 로그인을 기다리지 않는다(linger)**: "로그인 후 켜진다" 로 보인 건
  NetworkManager-wait-online(19~43 s)이 `os-led-display`(After=multi-user.target)와 RAY 재시작 시점을 로그인 시점과
  겹치게 만든 우연이었다.

## 노래 재생 툴 (`play_song` / `stop_song`)

2026-09-22 ~ 09-23. GPT-Live 세션 중에 노래를 틀고 끄는 백엔드 툴.

### 곡 고르기

- **목록 방식, 검색은 나중에**: 곡이 20개라 `play_song(song)` 의 `song` 을 카탈로그 키 enum 으로 고정하고, 사람이
  읽는 목록(제목·가수·별칭)을 툴 설명에 넣었다. 백엔드 LLM 이 "BTS 다이너마이트" → `Dynamite_BTS` 매칭을 직접 하므로
  왕복 1회이고, strict enum 이라 없는 곡을 고를 수 없다. 검색 툴(`search_song`)은 규모가 커지면 붙이되, 같은 카탈로그
  필드를 정규화해 훑는 전제다.
- **카탈로그는 파일명이 아니라 `assets/songs.json`**: 파일명은 `IAM`(가수 없음), `Drawer_10cm`/`10CM_pet`(순서
  뒤바뀜), `Your_Existence_WONSTEIN`(한국어 제목의 영어 번역)처럼 규칙이 없어 LLM 매칭에 못 쓴다.
  - 키 = 파일 stem, `title` 은 공식 원어 하나, 사람들이 부르는 다른 이름은 `aliases`/`artist_aliases`.
  - 시작 시 네 파일 세트(wav·head·mouth·led CSV)를 대조해 빠진 곡은 경고와 함께 제외하고, 카탈로그에 없는 CSV 도
    경고한다. 그래서 "파일이 없어 재생 실패" 가 툴 단계에서 생기지 않는다.

### 스트림 교대와 툴 결과 보류

- **스트림 교대는 피할 수 없다**: C++ 메인 루프는 재생 하나(라이브 스트림 / 파일 / 노래 CSV)를 끝까지 블로킹으로
  처리한다. 라이브 세션은 스트림 하나로 돌아가므로, 노래를 틀려면 `audio_end` 로 닫고 `playback_complete` 를 받은 뒤
  `play_audio_csv` 를 보내고, 끝나면 `stream_start(live)` 로 다시 연다. GPT-Live 세션·마이크는 내내 살아 있다 — 인사
  WAV 재생 중과 같은 "세션은 열렸는데 출력 스트림은 없는" 상태를 재사용한다(그때 나오는 모델 음성은 버림).
- **`play_song` 결과는 노래가 시작된 뒤에 제출한다**: 백엔드 답은 대화 모델에 "말로 옮길 정보"(commentary)로
  들어가므로, 빈 답을 시켜도 모델이 위임 전후에 자기 말("그래, 틀어볼게", "방금 노래 틀었어")을 한다(실기 로그).
  - 결과를 즉시 제출하고 스트림을 닫자 그 말이 잘렸다.
  - 그래서 툴 결과를 Future 로 보류하고 → 출력 무음 1 s → `audio_end` → 노래 시작 → 그때 제출·`continue_response`.
    위임 때의 한마디는 다 나가고, 결과 뒤의 말은 스트림이 없어 버려진다.
  - 위임이 몇 초 열려 있는 셈인데, 웹 검색 위임도 그 정도 걸린다.
- **`stop_song` 도 결과를 보류한다 (STOPPING)**: 정지 위임 때 모델이 "응, 바로 끌게" 를 말한다. 정지 직후 스트림을
  바로 다시 열면 그 말이 노래가 이미 꺼진 뒤 들리고, 결과 뒤의 "멈췼어" 와 붙어 나온다(실기). 노래 중에는 말을 안
  하는 게 목표이니 "끌게" 는 들리면 안 된다.
  - 그래서 `stop` 은 즉시 보내 노래는 바로 끊되, 스트림은 닫힌 채 두고 모델 출력 무음 1 s 를 기다린 뒤(닫힌
    스트림에서도 음성 유무는 추적) 스트림을 열고 결과를 제출한다. "끌게" 는 버려지고 결과 뒤의 "껐어" 만 들린다.
  - 백엔드 복원은 정지 결과의 후속 응답 요청(`response.create`) 뒤에 한다.
  - 노래를 끄고 아무 말 없이 가만히 있는 게 어색하다는 실기 피드백으로, 정지 백엔드가 `stop_song` 뒤에 "The song
    has been stopped." 를 답하게 해 모델이 "노래 껐어" 를 말하게 했다(툴 확인 뒤 완료 보고).
- **대기 상한은 안전망이지 발화 절단기가 아니다**: 실기에서 모델이 결과를 기다리며 "지금 불러오는 중이야, 잠깐만"
  으로 5 s 를 채워 상한에 걸려 말이 잘렸다. 말이 길어지는 것보다 뚝 잘리는 게 더 큰 실패다.
  - 노래·종료 시퀀스의 상한을 30 s 로 올리고, 도달 시 WARNING(무음 감지 이상 신호)으로 남긴다.
  - 길어지는 말은 위임 정책에 "위임은 몇 마디로 받고, 기다림을 메우려 말하지 말라" 한 줄로 줄인다. "기다리는 동안
    조용히" 는 나중에 위임을 걸어 두고 대화를 이어 가는 용법과 충돌해 쓰지 않는다.

### 노래 중 청취

- **노래 중 CH0 는 장치가 게이트한다 → 원본 채널 + 모델 분리** (2026-09-22 실측): (→ 이후 노래 중에도 CH1 한 채널로
  통일 — [ReSpeaker 마이크](respeaker.md)의 "마이크 입력을 CH1 로" 항목)
  - reSpeaker XVF3800 은 음악을 재생하면 CH0 출력이 바닥(-46 dBFS)보다 낮은 -50~-61 dBFS 평탄으로 떨어져 사용자
    음성이 전혀 안 나온다. 스피커를 꺼도 같다(참조가 USB 재생 스트림 자체). 후처리 파라미터(`PP_ECHOONOFF` 등)로도
    안 풀린다.
  - 음성 재생(TTS 67 s)에서는 더블토크가 통과했으므로 고장이 아니라 소스 특성이다. 노래는 같은 볼륨에서 RMS 11 dB
    높고 20 ms 활동률 98%, 시간·주파수 점유 32%(음성 4.6%)라 근단이 이길 빈칸이 없다.
  - 그래서 재생 중에만 `AudioInput.set_raw_capture(True)` 로 원본 CH2(+15 dB)를 쓴다. 스트림은 6채널로 이미 열려
    있어 채널 선택은 슬라이싱이고, 다음 30 ms 프레임부터 바뀐다.
  - 원본 채널에 음악이 그대로 섞여도(rms -37 dBFS) GPT-Live 는 사용자 전사 5/5 정확·가사 전사 0 이었고, 모델 스스로
    "음악은 배경처럼 깔려 있고 네 목소리가 또렷" 이라 답했다. `stop_song` 은 "노래 꺼줘" 발화 끝 ~1.3 s 뒤 호출됐다.
- **지시문 두 가지 함정**:
  1. 재생 중 "말하지 말고 조용히 있어라"(`silent`)를 얹으면 응답뿐 아니라 **입력 전사까지 0** 이 된다. 전사가 별도
     인식기가 아니라 모델 출력이라는 관측([FINDINGS §3](../../scripts/gpt_live/FINDINGS.md#3-전사-transcript))과
     맞는다. 그래서 "음악은 배경, 사람 말에는 평소처럼 답하라" 로 쓴다.
  2. "가사를 인용하지 말라" 는 가사 질문까지 거부하게 만들어 뺐다.
- **위임 정책에 노래가 있어야 한다**: 노래 항목이 대화 모델의 시작 지시문 위임 정책에 없으면 "노래 꺼줘" 에 말로만
  "끌게" 하고 위임하지 않는다(2/2). 시작 지시문의 두 목록(백엔드 툴 / 위임 조건)에 음악 항목을 그냥 넣었고, 카탈로그
  유무로 조건부를 두지 않는다. 재생 중 지시는 `instructions.append` 로 얹고 끝나면 해제한다.

### 재생 중 상태 — 멈추기만 가능

- **백엔드를 갈아 끼운다**: 백엔드 설정(instructions·tools)은 `session.update` 로 세션 중 바꿀 수 있는 유일한 영역이고,
  위임마다 새 요청이라 상태가 없다.
  - 기본 백엔드에는 `play_song` 만 두고, `play_song` 요청을 받아들인 순간 백엔드를 `stop_song` 하나 + "멈추라면
    stop_song, 아니면 아무것도 하지 말고 빈 답" 으로 교체한다. 노래 상태가 끝나면 복원한다.
  - 실기에서 재생 중 "종료" 가 `end_conversation` 으로 위임돼 세션이 끝난 적이 있다. 대화 모델 지시만으로는 못 막아
    툴을 빼는 쪽이 확실하다.
  - 수락 시점에 바꾸는 이유: 노래 시작 전 2 s 창에서도 정지가 통하고, 보류했던 `play_song` 결과에 대한 백엔드 후속
    응답("지금 틀었어…")도 교체된 백엔드(빈 답)로 돈다.
- **코드 쪽 방어도 둔다**: 노래 상태에서 `stop_song` 외 툴 호출은 오류이고, `end_conversation` 은 종료로 치지 않는다.
  종료 키워드도 재생 중엔 무시한다.
- **대화 모델 쪽 지시는 한 줄**: "노래 재생 중, 멈추라면 위임, 그 외엔 응답하지 말라".
- **전사는 저장하지 않는다**: 원본 채널은 빔포밍·잡음 억제가 없어 옆사람 대화가 들어오고, 모델 답은 스트림이 없어
  소리로 나가지 않는다.
- **유휴 타임아웃**: 재생 중엔 멈추고, 끝난 시점부터 다시 센다.
- **범위**: 곡 이름 없이 "노래 틀어줘" 는 대화 모델이 되묻는다. 재생 중 다른 곡으로 바꾸기, 일시정지·다음 곡은 범위
  밖이다. 검색 툴과 노래가 끝난 뒤 모델의 한마디("어땠어?")는 넣지 않았다 — 끝나면 조용히 듣기 상태로만 돌아간다.

### 지시문과 로그

- **지시문은 최소로**: 필수 문장만 넣고 문제가 보이면 추가한다.
- **위임·백엔드 답을 INFO 로 남긴다**: 기본 로그로는 함수 툴 콜만 보여 "위임 안 함 / 위임했지만 툴 안 부름" 을 구분할
  수 없었다(모델이 "대화도 종료할게" 하고 위임 없이 침묵한 사례). `Delegation created`, `Backend reply` 두 줄을
  INFO 로 남긴다.

### 실기 관찰

- **1차 (2026-09-22)**: 시퀀스 정상. 정지는 발화 끝 0.15 s 뒤 `stop_song`. 남은 문제:
  - 대화 모델이 곡 목록을 지어내고("Pray, Starlight…", 목록은 백엔드 툴 설명에만 있음) 백엔드가 없는 곡을 비슷한
    곡으로 틀어 버림. (→ 2026-09-23 목록 질문은 위임하게 함. 되묻는 순간의 예시는
    [차후 고려](../decisions-wip.md#차후-고려)에 남음)
  - 정지 뒤 모델이 두 번 말함("응, 바로" / "응, 멈췼어").
  - "10CM" 을 글자 그대로 읽음.
- **2차 (2026-09-23, 백엔드 교체 뒤)**:
  - 노래 중 "소리 좀 줄여줘" 에 정지 전용 백엔드가 `stop_song` 을 불렀다. 툴이 하나뿐이면 관련 요청을 전부 그 툴로
    몰아넣는 경향이다. "아니면 아무것도 하지 말라" 가 약하다.
  - 보류한 `play_song` 결과에 대한 후속 멘트("틀어뒀어. 10CM의 서랍이야")가 백엔드 교체 뒤에도 나왔다(스트림이
    없어 들리진 않음). 교체가 진행 중 위임의 후속에 적용되지 않거나, 대화 모델이 백엔드 텍스트와 무관하게 위임
    완료를 스스로 마무리하는 것이다.
  - **모델이 스스로 "대화도 종료할게. 안녕!" 하고는 위임 없이 침묵**: 정지 직후 "소리 줄이고, 노래도 멈췼어. 그리고
    대화도 종료할게. 안녕!" — `end_conversation` 위임은 없었고, 이후 100 s 동안 사용자가 계속 말을 걸어도 전사·응답이
    전혀 없었다(전사는 모델 출력이므로 모델이 "끝났다" 고 보고 입력을 무시한 것으로 해석). 사용자가 "종료 안 됐다,
    종료해" 라고 하자 그제야 백엔드가 `end_conversation` 을 불러 끝났다.

## 노래 음원 레벨 정규화

2026-09-28. 차임·인사에 이어 노래도 컸다. 20곡 실측에서 40ms 프레임 중앙값이 0.621 — 말소리(0.12)보다
**+14.3 dB**. 곡간 편차도 18 dB(TICK_TOCK 0.974 ↔ Pavarotti 0.119)라, "전체가 크다" 보다 "곡마다 들쭉날쭉" 이 더 큰
문제였다.

- **런타임 게인이 아니라 음원 자체에**: 노래는 `play_audio_csv` → `csv_control_motor()` → `sf::Music` 으로 파일에서
  직접 스트리밍한다.
  - `read_and_split` 의 int16 변환 지점을 안 지나가고, Python 은 경로가 아니라 `audio_name` 만 보내 C++ 이
    `assets/audio/music/<name>.wav` 를 조립한다. 그래서 차임·인사에 쓴 "정규화 사본 경로를 대신 재생" 수법이 안 통한다.
  - 남는 자리는 `sf::Music::setVolume()` 인데(당시 미호출 = 100 고정), 거기까지 값을 나르려면 브리지 프로토콜 + C++ +
    곡당 레벨 캐시(30~45 MB 디코딩)가 붙는다.
  - 반면 곡 추가는 이미 모션 CSV 3종 + 보컬을 만드는 수동 절차라, 음원 정규화 한 단계를 더 붙이는 비용이 거의 0 이다.
- **순서: 궤적 생성 → 정규화**: 입·머리 궤적은 오디오 레벨에서 뽑으므로, 줄인 음원으로 뽑으면 입이 작아진다. 이미
  만들어 둔 CSV 는 음원을 나중에 줄여도 그대로 유효하다(재생만 작아진다).
- **목표 0.18 = 말소리 +3.5 dB**: 차임은 말소리보다 *아래*로 잡았지만 노래는 재생 중엔 주인공이다. 정확히 말소리
  높이(0.12)로 내리면 배경음악처럼 들릴 위험이 있어 조금 위에 놓았다. 귀로 조정할 값이다.
- **증폭은 피크 천장에 걸려 안 된다**: Pavarotti 는 중앙값 0.119 로 목표보다 작지만 절대 피크가 0.861 이라 올리면
  클리핑한다. `PEAK_CEILING` 클램프가 배율을 1.03 으로 묶어 사실상 그대로 남는다 — 다이내믹이 살아 있는 클래식
  녹음이라 이게 맞다. 결과적으로 이 곡만 나머지보다 4 dB 작다.
- **되돌릴 수 있게**: 원본을 `var/audio/music_original/` 로 복사한 뒤 덮어쓰고, `--restore` 로 되돌린다. 재실행은
  목표 ±1 dB 안이면 건너뛴다 — 1 dB 여유는 감쇠 뒤 재측정이 목표보다 최대 1 dB 높게 나오기 때문이다.

## 기록 당시 남은 문제

- **재생 중 백엔드 교체의 한계** (실기 2차): 볼륨 요청에도 `stop_song` 을 부름, 보류 결과의 후속 멘트가 교체 뒤에도
  나옴.
- **모델의 자체 종료 선언 뒤 침묵** (실기 2차): 그 100 s 동안 유휴 타임아웃(60 s)이 안 걸린 것도 확인 필요 — 빈 텍스트
  전사 이벤트가 `_last_transcript_time` 을 계속 갱신했을 가능성.
- **실기 1차의 나머지**: 없는 곡을 비슷한 곡으로 틀어 버림, 정지 뒤 두 번 말함, "10CM" 을 글자 그대로 읽음.
- **"Do not respond to anything else" 가 정지 위임까지 막는지** 실기 확인 항목 — 앞선 `silent` 실측에서 "말하지
  말라" 가 전사를 0 으로 만든 적이 있다.
- **실기 미검증**: 백엔드 교체·복원이 발화를 끊지 않는지, 원본 채널 게인 15 dB 의 실내 잡음 영향.
- **부팅 1차 기동 실패**: ray-python 1차 기동이 `local_files_only=True` 인데도 HF 허브를 찌르다 DNS 실패로 죽고
  재시작한다(~25 s 손실). LED 진단 중 발견한 별건.
