# ReSpeaker XVF3800 에코 캔슬 이상 상태 (더블토크 끊김)

## Summary

로봇이 말하는 중에 사용자가 끼어들면 그 말이 짧은 조각으로만 전사되는 현상. XVF3800 이 에코를 제대로
빼지 못하는 상태에 들어가, 처리 출력(CH0)이 재생 중 근단 음성을 거의 통째로 억제하고 있었다.
설정값은 정상 상태와 같았고, **보드의 물리 RST 버튼으로만 풀렸다** — 파이프라인이 시작마다 보내는
소프트웨어 리셋(USB REBOOT 명령)으로는 풀리지 않았다.

- **확인**: 2026-10-13
- **원인**: 미확정. 라즈베리파이(=ReSpeaker 전원)가 9/30 부터 13 일간 꺼진 적 없었다 — 장시간 통전 상태가 의심되나 미검증
- **조치**: 당분간 증상이 보이면 전원을 완전히 내렸다 올린다(또는 RST 버튼). 자동화는 미적용 (아래 "자동 복구")
- **상태**: 열림 — 재발 계기 미확인

## Environment

- **Board**: Raspberry Pi 5, kernel 6.8.0-1063-raspi
- **Mic/Speaker**: Seeed reSpeaker Flex XVF3800 **L16K6Ch**(선형 4마이크, USB `2886:0022`, 펌웨어 1.0.3), Pi USB 포트 직결(`2-2`)
- **볼륨**: 10/10 (장치 `PCM Playback Volume` 60/60)
- **엔진**: GPT-Live — 마이크는 CH0 만 보낸다(`voice_pipeline/adapters/audio_input.py`)

## Symptom

- 모델이 길게 말하는 중 사용자가 끼어들면 "톡", "자", "저", "조용", "어" 같은 한 음절만 전사되고, 모델은 말을
  멈추고 "응? 네?" 로 받는다. 사용자 체감: "너가 말하고 있는 사이에는 내 말이 잘 안 들린다".
  (로그 `var/log/pipeline/20261013_144640.log`, `20261013_145113.log`, `20261013_150211.log`)
- 에코가 새어 들어가 생긴 헛전사가 아니라, 실제 사용자 발화가 잘려 들어간 것이다.

## 채널 구성 (6ch 펌웨어)

Seeed 문서 기준. 코드에 있던 "CH1 은 에코 통과" 가정은 틀렸다.

| 채널 | 내용 |
|---|---|
| CH0 | 처리 출력 (Conference) — AEC·빔포밍·후처리(에코 잔여 억제·잡음 억제·AGC) |
| CH1 | 처리 출력 (ASR) — AEC·빔포밍만, 후처리를 거치지 않는다. CH0 보다 약 25 dB 작다 |
| CH2–5 | 마이크 0–3 원본 — **게인 없음** |

원본 채널이 말소리 기준 −75 dBFS 안팎(잡음 바닥 −78)으로 매우 작은 것은 고장이 아니다. XMOS 문서: 원본
마이크에는 게인을 적용하지 않으며, 큰 소리에서 클리핑하지 않도록 맞춰져 있어 그대로 들으면 작다.
조사 중 마이크 보드가 거꾸로(수음 구멍이 뒤쪽) 달려 있던 것을 바로잡았으나 원본 레벨은 변하지 않았다.

## Investigation

`MIC_DUMP=1` 로 파이프라인의 6채널을 채널별 WAV 로 녹음하고(`var/log/mic/`), 별도 스크립트로 GPT-Live 목소리
TTS 를 `pw-play` 로 재생(C++ 와 같은 기본 싱크·같은 말소리 레벨)하면서 녹음했다(`var/probe/aec/`,
`var/probe/aec_series/`). 녹음 앞 6 초는 혼자 말하기(기준), 재생 중 끼어들어 말하기.

### 이상 상태 (물리 리셋 전)

- 재생 중 CH0 이 대부분 −51 dBFS 바닥에 평평하게 눌려 있고, 끼어든 말은 0.2–0.4 s 조각만 통과했다.
  같은 구간 원본 채널은 바닥보다 4–8 dB 올라와 있었다(사용자 발화로 추정).
- CH1 에 재생음이 선형 에코로 크게 남았다(아래 표 −55 dBFS). 귀로도 CH1 에서 에코가 간간이 새는 것이 들렸다.

### 정상 상태 (16:08 물리 RST 버튼 이후)

- CH0 은 더블토크 중에도 끊기지 않고, CH1 에서 에코와 근단이 뚜렷이 구분된다.
- 이어서 소프트웨어 리셋(16:15)을 보내고 다시 재 봐도 정상 유지. TTS 20 s 를 리셋 없이 5 회 연달아 재생해도
  CH1 레벨이 재생 전과 같았다(에코 잔류 없음) — 분 단위로 서서히 나빠지는 경향은 보이지 않았다.

### CH1 잔류 에코 (재생음으로 FIR 회귀해 설명되는 성분, 낮을수록 좋음)

| 녹음 | 상태 | CH1 잔류 에코 |
|---|---|---|
| `20261013_154301` | 이상 (물리 리셋 전) | −55.1 dBFS |
| `20261013_160852` | 물리 리셋 직후 | −75.9 dBFS |
| `20261013_161526` | 소프트 리셋 직후 (재생 6 s) | −67.0 dBFS |
| `20261013_162826_uncovered` | 그다음 | −69.3 dBFS |

원본 마이크(CH5)에 들어온 에코는 물리 리셋 뒤 세 녹음 모두 −77 ~ −78 dBFS 로 같았다 — 차이는 음향 경로가
아니라 칩의 에코 제거 성능에서 나온다.

### 설정값은 두 상태가 같다

`xvf_host.py` 로 읽은 값. 이상 상태(15 시대)와 물리 리셋 뒤가 같았다: `AUDIO_MGR_MIC_GAIN` 10,
`AUDIO_MGR_REF_GAIN` 1.9, `AUDIO_MGR_OP_L` [8, 0], `AUDIO_MGR_OP_R` [7, 3]. 물리 리셋 뒤에만 읽은 값(소프트 리셋
뒤에도 같음): `AUDIO_MGR_SYS_DELAY` 12, `AEC_FAR_EXTGAIN` −20, `AEC_MIC_ARRAY_TYPE` 1(선형). 파이프라인은 시작마다
REBOOT 하므로 런타임에 바꾼 값은 남지 않는다 — 설정 문제가 아니라 칩이 돌고 있는 상태의 문제로 본다.
`PP_AGCGAIN` 은 이상 상태에서 상한(32)에 붙어 있었으나 정상 상태에서도 32 가 관찰돼 판별 지표가 아니다.

### 소프트웨어 리셋 ≠ RST 버튼

- 이날 14:44–16:00 파이프라인 시작마다 REBOOT 가 나갔지만 이상 상태는 그대로였고, 16:08 물리
  버튼으로 풀렸다. 커널 로그상 그 외 예상 밖의 USB 끊김은 없었다.
- 정상 상태에서 REBOOT 를 보내도 나빠지지 않았다 → REBOOT 는 원인이 아니지만 복구 수단도 아니다.
- REBOOT 는 XVF3800 펌웨어 재시작이고, 버튼은 RST_N 하드웨어 리셋이다. 버튼 쪽이 보드의 다른 부분(코덱·
  클럭 등)까지 초기화하는 것으로 추정.

## 자동 복구 — 확인한 것

| 방법 | 결과 |
|---|---|
| USB REBOOT 명령 (현재 파이프라인) | 이상 상태를 풀지 못함 |
| `uhubctl -l 2 -p 2 -a cycle` (2.5.0) | 허브는 `ppps` 로 보고하지만 커널이 1 s 안에 포트를 다시 켜 재열거. LED 안 꺼짐 |
| sysfs `usb2-port2/disable` = 1 | 장치는 USB 에서 사라지나 **LED 그대로 — VBUS 가 끊기지 않는다** |
| 전원 완전 차단 | LED 꺼짐 — 보드 전체 리셋 |

Pi 5 본체 포트로는 소프트웨어 전원 차단이 안 된다. 코드로 버튼과 같은 효과를 내려면 Pi GPIO → 보드 RST 헤더
배선(XIAO 용 하드웨어 리셋 라인과 같은 신호) 또는 포트별 전원 스위칭 허브·5V 릴레이가 필요하다. OS 종료만으로
USB 전원이 끊기는지는 미확인(부트로더 `POWER_OFF_ON_HALT` 미설정 = 기본값) — 어느 쪽이든 다시 켜 줄 사람이 필요해
자동 복구 수단은 아니다.

## 측정 시 주의

- **채널마다 지연이 다르다**: CH1 은 원본보다 약 50 ms 늦다. 재생음과 정렬은 채널별로 따로.
- **재생 시작 지연이 들쭉날쭉하다**: 싱크가 유휴로 잠들었다 깨면 `pw-play` 시작이 수백 ms 늦어진다. 정렬
  탐색 범위가 좁으면 정렬에 실패해 "에코가 없다" 로 잘못 읽힌다(1.5 s 이상 잡을 것).
- **CH0 은 잔류 에코 측정에 부적합**: AGC·억제로 게인이 계속 변해 선형 회귀가 맞지 않는다. CH1 로 본다.
- **Pi 에서 무거운 회귀를 병렬로 돌리지 말 것**: 프로세스 4 개 × BLAS 스레드 4 개로 메모리·CPU 가 바닥나 Pi 가
  멈췄다. 단일 프로세스·`OPENBLAS_NUM_THREADS=1` 로, 재생 구간 일부만.
- 녹음은 레벨 그대로 저장하고 들을 때만 사본을 키운다(CH1 +25 dB, CH2–5 +45 dB 면 대략 CH0 과 비슷하게 들린다).
