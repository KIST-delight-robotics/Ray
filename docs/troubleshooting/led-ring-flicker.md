# LED 링 임의 색 깜박임 — 링 보드 불량

- **진단**: 2026-09-11
- **원인**: 링 보드 불량 (체인의 특정 구간 이후만 깨짐)
- **조치**: 링 보드 교체로 해소

## 진단 경과

- **증상**: RAY 기동 후 링 LED 에 흰색·잡색 픽셀이 간헐적으로 튀었다. 데몬 재시작(`install.sh`) 때의 ATtiny 동시
  드라이브 깜박임과 겉보기가 같아 처음엔 그쪽으로 추적했다.
- **판별 순서와 기각**:
  1. arbiter 로그로 두 Pi 프로세스 충돌이 아님을 확인.
  2. SPI 열기·설정만 하는 프로브로 "열기 글리치" 기각.
  3. RAY·데몬을 다 끄고 Pi 가 직접 회색 프레임을 60 fps 로 쓰는 프로브에서는 깨끗했다.
  4. 그런데 **데몬이 꺼져 ATtiny 만 그리는 상태에서도 링 아래 8개만 튀었다**. 5 V 소스에서도 그랬다. 체인의 특정
     구간 이후만 깨지면 신호가 아니라 그 경계의 하드웨어다. 링 보드 교체로 해소됐다.
- **교훈 1 — 색으로 원인을 가를 수 없다**: 두 송신기가 겹쳐도 비트가 섞여 임의 색이 나온다. "임의 색 = 신호 노이즈,
  노랑 = ATtiny" 라는 구분은 틀렸다.
- **교훈 2 — 갱신 주기가 가시 시간을 정한다**: 깨진 픽셀은 다음 프레임에 덮인다. 데몬 60 fps(16 ms)·RAY 정적
  10 fps(100 ms)에선 "파박" 으로만 보이고, ATtiny IDLE(검정 1 s 재전송)에선 1초씩 남아 또렷하다. 같은 불량이
  상황마다 다르게 보였던 이유다. 펌웨어의 "IDLE 검정 재전송(유령 픽셀 방지)" 도 같은 계열의 증상을 덮던 것일 수 있다.
- **교훈 3 — 격리는 소스를 바꿔서**: Pi 가 그릴 때와 ATtiny 가 그릴 때 둘 다 재현되면 소프트웨어·레벨(3.3 V)·모터
  노이즈가 한 번에 빠진다. 인덱스 범위로 일부만 켜서 어디부터 깨지는지 찍으면 위치가 나온다.
- **부수 확인 — 부팅 시 RAY 는 로그인을 기다리지 않는다(linger)**: "로그인 후 켜진다" 로 보인 건
  NetworkManager-wait-online(19~43 s)이 `os-led-display`(After=multi-user.target)와 RAY 재시작 시점을 로그인 시점과
  겹치게 만든 우연이었다.
