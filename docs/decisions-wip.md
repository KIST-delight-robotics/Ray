## GPT-Live 장기기억 1차 — 검색 트리거를 백엔드 위임으로, 세션 컨텍스트는 시작 instructions 로

cascade 의 "매 턴 검색 → 블록 주입" 은 live 엔진에서 성립하지 않는다. 턴 경계가 없고, instructions 는 시작 후 고정이며, 세션 중 주입은 append 3종(≤500 토큰)뿐인데 `instructions.append` 는 발화를 끊는다. 변경을 최소로 두고 기존 memory 서브시스템(storage / retriever / writer)은 그대로 쓴다.

- **검색 트리거·쿼리 생성은 백엔드 LLM**: `search_memory(query)` 를 responses 위임 백엔드의 함수 툴로 준다. 대화 모델이 "과거 대화" 를 위임 대상으로 판단하고, 백엔드가 이력 전체를 보고 쿼리를 쓴다 — cascade 의 "직전 N턴 concat" 보다 맥락이 낫다. 트리거가 두 모델로 갈라지므로 위임 정책 템플릿(Backend tools / Delegate when / Do not delegate when)에 항목을 넣되 규칙을 덧붙이지 않는다(위임률은 형식에 좌우, 위 항목). 대가는 지연(위임→툴→발화 약 2초 + 임베딩)과 **암묵적 회상의 소실** — "영화 추천해줘" 에 취향을 반영하는 식은 위임되지 않는다. 암묵적 회상은 별도 기능(`thinking.append` 경로)으로 다룬다.
- **선별은 백엔드가 한다**: 대화 모델은 검색 원문을 보지 않고 백엔드의 최종 텍스트만 받아 패러프레이즈한다. 핸들러는 retriever 상한(10개)을 그대로 돌려주고 토큰 캡을 두지 않는다 — 백엔드 입력이라 대화 모델 컨텍스트를 차지하지 않고, 백엔드 지시문의 "현재 질문에 맞는 것만 쓰라" 가 선별을 맡는다. 결과 없음은 명시적 JSON 으로 돌려준다 — 백엔드가 "web search 쓰지 마라" 는 무시하는 경향이 있어(FINDINGS §4) 빈 결과에서 웹으로 새지 않게 지시문에 함께 적는다.
- **인용·retained buffer 는 쓰지 않는다**: `[MEMORIES: M1]` 태그는 우리가 파싱할 LLM 출력이 없고, TTL 은 턴 단위라 이 엔진에서 의미가 없다. retriever 는 그대로 쓰되 `update_citations` 를 부르지 않는다 → `last_cited_at` 이 갱신되지 않아 recency 감쇠는 생성 시각 기준. 검색 결과는 대화 모델 컨텍스트에 남지 않으므로 후속 질문은 재위임된다(백엔드는 자기 이력에서 직전 결과를 볼 수 있어 재검색 없이 답할 수도 있음).
- **프로필(블록 2)·최근 세션(블록 3)은 시작 instructions 에**: 16,384 토큰 한도에 프로필 256 + 최근 세션 512 soft cap 이라 여유가 크다. 블록 3 을 넣는 이유는 "지난번에 얘기한 거" 류가 검색 없이 풀려 지연과 위임 누락 위험이 줄기 때문. 검색 제외 집합은 cascade 와 같은 불변식("블록에 있음 ⟺ 검색 제외"): 현재 세션 + 블록 3 에 실제 포함된 세션. 이월(블록 4)은 넣지 않는다 — 직전 세션 추출이 끝나기 전 다시 깨우면 그 세션이 어디에도 없는 공백은 1차에서 감수. 로더는 `ContextBuilder` 의 것을 모듈 함수 `prompt.load_session_context` 로 꺼내 두 엔진이 공유한다.
- **쓰기는 이미 동일**: live 루프가 닫힌 전사 세그먼트마다 utterance 를 저장하고, FAREWELL 의 `MemoryWriter.process_session` 은 엔진 무관. 손대지 않았다.
- **툴 핸들러는 executor 에서**: 프레임 루프는 100 ms 마다 마이크 전송과 출력 중계를 해야 하는데, 임베딩(MiniLM on Pi 5)과 DB 조회가 그 안에서 동기로 돌면 그만큼 오디오가 멎고 C++의 재생 여유를 깎는다. `_on_response_done` 은 submit 만 하고 프레임 루프가 완료를 폴링해 결과를 제출한다. 종료 시퀀스 중 도착한 결과는 버린다 — 이어가면 모델이 새 발화를 시작해 종료가 늦어진다. `executor=None` 이면 인라인(테스트).

## 장기기억 상시 컨텍스트 재설계 — 프로필은 정체성 사실·선호 목록만, 최근 맥락은 원문, 시각은 현지

- **취향·성격을 상시 컨텍스트에서 뺀다**: Memobase 식 슬롯 프로필이 실데이터에서 해석을 쌓았다 — 한 번의 반응이
  성격 특성이 되고(레이가 잘못 알아들어 짜증 낸 순간 → `traits`), 라디오 주제가 관심사가 되고, UPDATE 가 문장
  덧붙이기라 상충하는 선호가 한 슬롯에 공존했다(`tone_preference` 에 playful 과 refined). 출처·근거 횟수가 없어
  철회할 길도 없다. live 에서는 "아는 것으로 답할 수 있으면 위임하지 말라" 때문에 모호한 슬롯이 정확한 에피소드
  검색을 막기까지 한다 — 어설픈 프로필은 없는 것보다 나쁘다. 대가: 암묵적 회상 계획이 없으므로 레이가 취향을
  먼저 꺼내는 일은 없어진다. 받아들임.
- **상시 블록 = 프로필(누구인가) + 선호(어떻게 답하길 원하나)**: 기준은 "모델이 필요를 알아차릴 수 없는데 적용돼야
  하는 것" — 위임은 사용자 발화가 필요를 드러낼 때만 작동한다. 프로필은 사용자가 자기 자신에 대해 단정적으로 말한
  정체성 사실(이름·하는 일·직장·전공·사는 곳·가족)만. "몇 달 뒤에도 그대로" 는 한 세션 원문만 보는 추출기가 판정할
  수 없어 말의 형태(정체성 단언 vs 상태·사건·지나가는 언급)로 바꿨다. 선호는 레이에게 직접 한 요청 중 지속
  표지("앞으로", "항상")가 있는 것만 — 반응에서 추론하지 않고, 세션 안 요청은 대부분 그 순간용이다. 놓친 선호는
  다시 말하면 되지만 잘못 박힌 선호는 매 세션 말투를 비튼다.
- **슬롯 대신 항목 목록, 갱신은 연산으로**: 슬롯은 분류를 한 번 더 시켜 틀릴 자리를 만들고(`communication_style` 이
  세 topic 에 흩어짐), 키 문자열이 어긋나면 기존 슬롯을 못 봐 중복 행이 생기고, 빈 칸이 채우기 압력이 됐다
  (`language` 에 "engages with music and storytelling"). 목록이 작아 갱신 호출에 전체를 보여줄 수 있으니 키 매칭이
  필요 없다. 출력을 전체 재작성으로 받지 않는 이유는 재작성 드리프트 — 무관한 줄도 매 세션 LLM 을 거쳐 표현이
  바뀌거나 빠진다. 추가·교체·삭제 연산만 받으면 손대지 않은 줄은 코드가 보존하고, 추출+병합 2회 호출이 1회가 된다.
- **노트 갱신은 에피소드가 0개여도 돈다**: 예전엔 에피소드가 나와야 프로필을 추출했는데, "앞으로 반말해" 한마디
  세션은 사소하다고 에피소드 0개가 나오기 쉬워 그 선호가 버려졌다. 기존 `profiles` 테이블은 지우지 않고 버려 둔다 —
  저장소는 열 때마다 마이그레이션을 돌리므로 DROP 을 넣으면 예전 벤치 run 의 DB 까지 여는 순간 지워진다.
- **최근 세션 에피소드 블록 → 최근 대화 원문 꼬리**: 에피소드 블록은 최근일 뿐 관련 있지는 않고, 가장 자주 참조될
  직전 세션이 추출 지연으로 가장 자주 빠진다. 요약은 세션 끝 LLM 호출이라 같은 지연이 생기지만 원문은 턴 경계에서
  이미 저장돼 있다. 직전 1세션이 아니라 세션 경계를 넘어 토큰 예산(1.5k)만큼 거꾸로 채우는 이유는 책상 로봇 세션에
  한마디짜리가 많아서. cascade 는 에피소드 블록 그대로.
- **과거 원문이 지금 요청으로 읽히지 않는다 (실측 2026-10-28)**: 라이브 지시문 전문이 백엔드에도 가므로(FINDINGS §4)
  어제 세션이 "잘 자"·"라디오 틀어줘"·"아이엠 틀어줘" 로 끝난 꼬리를 넣고 무관한 요청을 위임했다 — 백엔드가 과거
  줄의 툴을 부른 것 0/40. 지난 기록이라는 머리말은 그래서 넣지 않았다. 실작동 경로(`pipeline_harness`, 실제
  GPT-Live)에서도 8/8: "어제 내가 뭐 했다고 했지?" 에 위임 없이 원문으로 답("사랑니 뽑았다고 했어요"), 어제의 작별
  뒤 "피곤하네" 에 작별하지 않음, 어제의 "라디오 틀어줘" 뒤 "안녕" 에 라디오 안 켬, "어제 그 노래 다시" 에 IAM 재생.
- **백엔드는 답이 지시문에 있어도 검색부터 한다 → "아는 것으로 답되면 검색 말라" + live 검색 제외 해제**: 답이
  꼬리에 있는 "어제 틀었던 그 노래 다시 틀어줘" 에 백엔드가 search_memory 부터 부른 것이 6~9/10. 그런데 지시문에 든
  세션은 검색에서 빠져 있어 빈 결과를 받고, 지시문은 "맞는 게 없으면 기억 안 난다고 하라" — 지시문에 있는데 "기억
  안 나요" 가 될 수 있었다(에피소드 블록 시절에도 같은 구조). 지시문 한 문장으로 바로 트는 비율이 4/10 → 9/10,
  꼬리에 없는 질문은 여전히 10/10 검색. 질문형("어제 무슨 얘기 했지?")은 여전히 8/10 검색해 문장만으로는 못 막으므로
  제외도 없앴다. 제외는 cascade 가 같은 에피소드를 블록 3 과 매 턴 검색 블록에 두 번 넣지 않으려던 것인데, live 의
  검색 결과는 백엔드 툴 출력으로만 가서 겹칠 일이 없다.
- **모델에게 보이는 시각은 현지 시각 + 상대 시간, 현재 시각은 세션 경계 표시로**: 저장은 UTC 그대로. 헤더가 UTC 를
  표시 없이 보여 06:05(KST 15:05)를 아침으로 읽을 수 있었고, 대화 모델은 날짜를 몰라 어제와 일주일 전을 가르지
  못했다. 상대 시간도 코드가 계산해 모델이 시차·날짜 계산을 하지 않게 한다. 요일은 고정 영문 약어 — 이 기기 로캘이
  한국어라 `%a` 를 쓰면 지시문에 한국어 요일이 섞인다. 라이브 지시문은 백엔드도 받으므로 한 번 넣으면 둘 다 본다.
  cascade 의 이월 헤더·경계 표시·검색 블록 날짜도 같은 함수로 바꿨다 — 최근 세션 헤더가 공유 함수라, cascade 만
  두면 한 프롬프트 안에 UTC 와 현지 시각이 섞인다.
- **날짜 범위 검색은 백엔드 LLM 이 날짜를 푼다**: `search_memory` 에 since/until. 03-read §5-1 의 dateparser 대신
  쿼리를 쓰는 백엔드 LLM 에 맡긴다 — 한국어 상대 표현("그저께", "저번 주")에 훨씬 강하다. 가장 큰 실패는 거짓
  정밀도("저번에" 를 지난주로 좁혀 3주 전을 놓침)라 달력 표현일 때만 범위를 쓰게 한다.
- **기간은 순위 매기기 전에 거른다, 범위 밖 상위 결과는 항상 딸려 보낸다**: 일반 검색은 전체 상위 K 를 뽑은 뒤
  거르므로, 비슷한 얘기가 다른 날 많으면 그 기간 에피소드가 상위 K 에 못 들어 사라진다. "범위+주제가 0건이면
  범위 없이 재검색" 은 성립하지 않았다 — 그 기간에 에피소드가 하나라도 있으면 유사도 순위는 항상 뭔가를 돌려준다.
  그래서 범위 밖 상위 3개를 늘 덧붙이고, 결과마다 붙은 날짜로 백엔드가 가린다("어제가 아니라 사흘 전"). 백엔드에
  재호출을 시키는 길은 지연 1 초와 지시 준수에 기대야 해 버렸다.
- **실측 (백엔드 모델, 케이스당 10회, 2026-10-28)**: 어제 10/10, 모호 표현("저번에", "예전에") 20/20 범위 없음,
  "지난주+주제" 10/10 이 지난주를 포함(7회는 정확히 월~일). 주제 없는 기간 질문에 query 를 "what we talked about
  yesterday" 로 채우던 것(5회 중 4회 — 기간 결과가 유사도 순이 되고 범위 밖 결과가 붙는다)은 인자 설명에 그 문장을
  예로 들어 "비워라" 하자 10/10 빈 query.
- **미룸**: 진행 중인 일(세 번째 목록) — 끝난 일을 되묻는 식으로 실패가 가장 눈에 띄는 기능이라, 같은 메커니즘이
  두 목록에서 안정된 뒤. 취향의 백엔드 배치 — 그 정보를 쓰는 작업(곡 제안)이 생길 때. cascade 를 같은 방식으로
  맞추는 것.

## 차후 고려

- **ReSpeaker 하드웨어 리셋 자동화**: Pi GPIO → 보드 RST 헤더 한 가닥이면 세션 시작마다 버튼과 같은 리셋을 걸 수
  있다(배선 필요). 이상 상태를 감지할 지표(`AEC_AECCONVERGED` 등)는 아직 없다 — 재발 시 상태값을 읽어 둘 것.

- **백엔드 툴·태스크 지시문 전반 정리**: 노래 작업 중 툴 규칙이 한 항목씩 덧붙여져 형태가 고르지 않다. 실기에서 드러난
  구멍 — "불 켜져 있냐" 를 밝기 조회(`get_device_settings`)로 연결하지 못해 확인 없이 "켜져 있어" 라고 지어냈고, 다시
  물으니 "확인할 수 없다" 고 답함(툴 설명·규칙이 "how loud or how bright" 만 언급, `brightness.level="off"` 를
