# DJ 모드 작업노트

레이가 라디오 DJ처럼 잔잔한 1인 방송을 진행하는 모드. 소재 하나를 자기 말로 풀고 노래 하나를 틀기를
반복하며, 사용자가 끼어들면 대화 상대로 전환했다가 돌아온다. 이야기 모드(2026-10-01 제거, 커밋 ab89ff5)를
대체한다. 상태는 진행 중. 확정된 결정은 작업이 끝나면 `decisions-wip.md` 로 옮긴다.

## 결정 사항 (2026-10-01)

- **진입은 백엔드 툴 `start_dj`.** 전사 키워드 매칭(종료 키워드 방식)이 아니라 위임 → 툴. 표현 변형을 모델이
  흡수하고, 툴 결과 → 이어가기가 첫 멘트의 트리거가 되어 별도 통보가 필요 없다. 진입 뒤 레이는 "시작할게요"
  없이 바로 오프닝으로 들어간다.
- **소재는 대화 모델에 `thinking.append`, 백엔드에 `## Current segment` 절.** 둘 다 넣는다. 백엔드에 넣는 이유:
  thinking 내용은 전사에 없어서, 사용자 질문으로 위임이 오면 백엔드가 소재를 모른다. 백엔드 쪽은
  `session.update` 교체라 쌓이지 않고(소재 하나 또는 없음), DJ 종료 때 `restore_backend`. 대화 모델 쪽은
  append 라 지울 수 없어 누적되지만 소재당 300~500 토큰이라 감당 가능. "최신 소재만 따르라" 지시로 관리.
  이야기 모드의 백엔드 교체 경합("다음 위임부터 적용")은 여기선 문제가 아니다 — `start_dj` 를 부른 위임은
  빈 응답으로 끝나고, 소재가 필요한 건 그 다음 위임이다.
- **진행 규칙은 세션 시작 지시문에 상시 포함.** DJ 모드가 아닐 땐 조건부로 잠든다. `instructions.append`
  주입은 500 토큰 한도와 발화 끊김 때문에 이야기 모드에서 보정을 세 번 했다.
- **상태의 주인은 루프 하나.** 백엔드는 세션 내내 같은 툴 집합. 모드 밖에서 DJ 툴이 불리면 오류를 돌려준다.
- **곡 재생은 인자 없는 `play_dj_song`.** 루프가 현재 세그먼트의 곡을 알고 있으므로 백엔드가 제목에서 id 를
  고를 필요가 없다. 재생 뒤 흐름은 기존 노래 상태 기계(PENDING → DRAINING → PLAYING) 그대로.
- **DJ 중 소재 관련 런타임 검색은 하지 않는다.** 이야기 진행은 대화 모델이 노트 안에서 한다. 검색은 사용자가
  물었을 때의 보조 수단. "그럴듯한 얘기" 는 노트의 밀도로 해결한다.
- **노래 자연 종료 → 다음 소재.** `playback_complete`(PLAYING) 에서 스트림 재개 → `thinking.append`(소재) →
  백엔드 소재 절 교체 → `instructions.append` 로 "다음 소재 시작" 깨우기. append 가 입력 역할을 한다는 근거는
  종료 시퀀스의 작별 인사 유도(commentary) 가 실기에서 모델을 말하게 한 것.
- **사용자가 노래를 멈추면 DJ 종료.** 다음 소재로 넘어가지 않는다. 노래까지 나왔으면 소재는 다 쓴 것이고,
  다시 들으려면 재진입하면 된다.
- **끼어들기 뒤 복귀는 앱이 시점을 정한다.** 모델에겐 "스스로 돌아가지 말라". 루프는 DJ 중·노래 아님·위임
  없음·사용자와 모델 둘 다 N초 무음이면 `instructions.append` 로 "이어갈지 짧게 물어라". 그 질문 뒤에도 N초
  무음이면 다시 append 로 이어가게 한다(옆에 틀어두는 사용 맥락에서 침묵은 듣고 있다는 뜻). N 은 모델의
  문장 사이 쉼(1~2초)보다 넉넉히, 5~6초에서 시작해 실기로 조정. 이야기 도중 모델이 위임 없이 멈춘 경우도
  같은 감시가 잡는다 — 지시에 "진행 중 멈춘 거면 묻지 말고 이어가라".
  배경: 이야기 모드에서 "답하자마자 틈 없이 이어가기" 가 문제였다. 답은 충분히, 복귀는 텀을 두고.
- **"잠깐만" 과 "그만" 은 첫 버전에서 둘 다 `stop_dj`(종료).** 종료 멘트는 "쉬어갈게요" 처럼 중립적으로.
  재진입은 "DJ 모드 시작해줘". 재진입 때 이전 소재는 건너뛴다.
- **소재 파일**: `assets/dj_segments/<이름>.md`, frontmatter 에 `song`(카탈로그 키)·`topic`, 본문은 불릿
  노트. 문장이 아니라 재료 목록이어야 한다(문장으로 쓰면 대본이 된다). 곡이 재생 불가면 로드 때 제외.
  순서는 랜덤, 재생 기록을 DB 에 남겨 세션을 넘어 중복 회피, 한 바퀴 돌면 오래된 순. 고유명사(10CM 등)는
  읽는 법을 노트에 적는다.
- **유휴 타임아웃(180초)은 그대로.** 레이가 말하거나 노래가 도는 동안은 갱신·정지되므로, 모든 게 멈춘 채
  180초면 끝나는 게 안전망이다.

## 실험 기록

### 2026-10-01 하네스(`scripts/gpt_live/mic_live.py --script`) 무개입 진행

입력은 TTS 로 "DJ 모드 시작해줘" 한 문장, 소재는 `thinking.append`(서랍 소재, 불릿 5줄), 소리는 스피커.

| 지시문 | 발화 | 결과 |
|---|---|---|
| DJ 규칙 + "roughly a minute" | 57초 | 노트를 순서대로 풀고 곡 소개 뒤 정지. 지어낸 사실·사연 없음 |
| DJ 규칙 + "roughly two minutes" | 82초 | 새 내용 없이 같은 생각을 감싸는 문장이 늘어남 |
| DJ 규칙, 분량 언급 없음 | 63초 | 자연 길이 ≈ 1분 |
| 운영 지시문만, 소재 없음 ("라디오 DJ처럼 혼자 진행해 봐") | 31초 | 명상 안내 같은 분위기 묘사. 할 말이 떨어져 정지, 이후 2분 침묵 |

- 트리거 한 번으로 곡 소개까지 멈추지 않고 가는 건 확인. 걱정했던 "중간에 멈추고 기다리기" 는 없었다.
- 소재가 없으면 정확히 "의미 없는 감상적인 얘기" 가 된다. 소재와 규칙 둘 다 필요.
- 분량은 지시문 숫자가 아니라 노트 밀도가 정한다. 2분을 원하면 노트를 두 배로.
- 노트 5줄이면 이야기가 노트의 윤곽을 그대로 따라간다. 재료를 더 주고 "전부 쓸 필요 없다" 가 나을 수 있다.
- **`thinking.append` 만으로 조기 발화**: 4회 중 1회, 요청을 듣기 전에 소재를 받자마자 말을 시작했다
  ("밤이 깊어지면 네, 디제이 모드로…"). 소재 주입은 툴 결과 제출 직전에 붙이고, 지시문에 "소재가 와도
  시작 신호 전엔 말하지 말라" 를 둔다.
- 모델은 어떤 식으로든 한 덩어리 말하고 멈춘다. 끝이 자연스러운 자리(곡 소개)는 괜찮지만, 노래 끝·끼어들기
  뒤처럼 끝이 없는 자리는 앱이 깨워야 한다.
- 부수: reSpeaker 가 전날 세션 뒤 재생 불가 상태로 남아 있었고 파이프라인이 시작 때 하는 USB 리셋
  (`adapters/respeaker.reset`) 으로 복구됐다. 하네스 단독 실험 전에 리셋이 필요할 수 있다.

### 실기 순서

1. 무개입 한 사이클: "DJ 모드 시작해줘" → 이야기 → 곡 소개 → `play_dj_song` → 노래 → 다음 소재 시작
2. 이야기 중 끼어들기: 답변 → 침묵 6 s → "이어서 할까요?" → 대답/침묵 뒤 복귀
3. 종료 경로: "그만", 노래 중 "꺼줘", 세션 종료 키워드
