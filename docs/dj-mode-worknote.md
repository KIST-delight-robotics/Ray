# DJ 모드 작업노트

레이가 라디오 DJ처럼 잔잔한 1인 방송을 진행하는 모드. 소재 하나를 자기 말로 풀고 노래 하나를 틀기를 반복하며,
사용자가 끼어들면 대화 상대로 전환했다가 돌아온다. 진행 중. 끝나면 결정은 `decisions-wip.md`, API 동작 사실은
`scripts/gpt_live/FINDINGS.md` 로 옮긴다.

쓰는 법: **현재 상태**는 코드와 맞게 덮어쓴다(이력은 커밋에). **관찰**은 조건·횟수·결과·스크립트만, 해석 없이.
**가설**은 근거와 반증 조건을 붙이고, 검증되면 관찰·현재 상태로 옮긴 뒤 지운다. **열린 질문**은 사용자가 정한다.

## 현재 상태 (2026-10-07, 곡 자동 재생 반영)

- **진입**: 사용자 요청 → 위임 → 백엔드 `start_dj`. 루프가 결과를 보류하고, 위임 시 모델의 한마디가 끝나 출력 무음
  0.5 s 가 되면 소재 `thinking.append` → 결과 제출 → 이어가기가 오프닝을 시작시킨다. 시작 신호(instructions.append)
  없음.
- **소재**: 대화 모델엔 `thinking.append`(모드 상태 한 줄 + 소재. 누적되므로 "최신 소재만"), 백엔드엔
  `## Current segment` 절(`session.update` 교체, DJ 종료 시 복원). 백엔드에도 넣는 이유: thinking 은 전사에 없어
  사용자 질문이 위임되면 백엔드가 소재를 모른다.
- **라이브 지시문**: 공식 템플릿 구조(정책 절 + `Backend tools` + 위임 정책 한 벌) 뒤에 모드 절, DJ 절은 Talk / Song /
  Listener interruption. 진행 규칙은 여기 상시 — instructions.append 는 500 토큰 한도와 발화 끊김이 있어서.
  진입 예시에 "디제이" 포함.
- **상태의 주인은 루프.** DJ 툴은 세션 내내 노출, 모드 밖 호출엔 오류.
- **곡은 앱이 튼다** (끼어들기 없이 이야기가 끝나는 경우, 루프 `DJWatch`):
  - 이야기는 고정 종료 문구 `"<artist>의 <title>, 들려드릴게요."` 로 끝내고 그 뒤엔 말하지 않게 한다(Song 절).
    곡 소개 뒤 위임 지시는 없다.
  - 소재를 넣은 뒤(진입·다음 소재 모두) **모델의 첫 음성부터** 지켜본다. 출력 전사 **끝**이 종료 문구(띄어쓰기·부호
    제거, 카탈로그 별칭 인정 — `dj.ends_with_closing_line`)이고 무음 **2 s** 면 곡을 튼다(노래 흐름의 무음 추가 대기 생략).
  - 문구 없이 무음 **3 s** 면 판정 요청: `response.item.create`(user 메시지 `DJ_CHECK_MESSAGE`) + `response.create`.
    규칙은 백엔드 지시문 DJ 블록 한 줄 — "이야기가 곡 소개까지 끝났으면 `play_dj_song`, 아니면 빈 응답". 메시지는
    세션 끝까지 백엔드 입력에 남으므로 "이번 요청에만" 이라고 적는다.
  - 판정 위임에서는 `play_dj_song` 외 툴을 실행하지 않고 "빈 응답으로 끝내라" 결과를 돌려준 뒤 이어간다
    (`end_conversation` 으로 세션이 끝나지 않게).
  - 곡이 아니면(빈 응답·텍스트·실패·15 s 무응답) 출력 무음 0.5 s 뒤 `DJ_RETURN_INSTRUCTIONS` → 다음 첫 음성부터 다시
    지켜본다. 이어가기 횟수 상한 없음. 복귀 신호에도 말이 없으면 처리 없음(같은 침묵에 6 s 신호도 안 보냄).
  - 무음은 **받은 무음 조각 길이**로 센다 — 발화 중 네트워크 정지(1.0~1.6 s, 09-17)를 쉼으로 보지 않기 위해.
  - 감시 중 새 사용자 전사가 생기면 그 소재의 감시를 끈다(**임시** — 끼어들기 분기 설계 전까지). 이후는 아래 복귀
    신호와 사용자 요청으로 진행.
  - 사용자 요청 `play_dj_song`(인자 없음 → 현재 소재의 곡)은 그대로. 앱 재생과 겹치면 "already playing".
- **노래 자연 종료** → 다음 소재 thinking + `DJ_SONG_ENDED_INSTRUCTIONS`. **사용자가 노래를 멈추면** DJ 종료.
- **복귀**: DJ 중·노래·위임 없음·사용자와 모델 모두 6 s 무음이면 `DJ_RETURN_INSTRUCTIONS` 한 번(침묵당 1회).
  이야기 끝을 지켜보는 동안(LISTENING/CHECKING)은 보내지 않는다. 모델에겐 "스스로 돌아가지 말라".
- **"잠깐만"·"그만"** 은 둘 다 `stop_dj`(종료). 종료 멘트는 중립("쉬어갈게요"). 재진입 때 이전 소재는 건너뛴다.
- **런타임 검색 안 함**: 이야기는 노트 안에서. 검색은 사용자가 물었을 때만.
- **소재 파일**: `assets/dj_segments/<이름>.md`, frontmatter `song`(카탈로그 키)·`topic`, 본문은 불릿 재료 목록(문장으로
  쓰면 대본이 된다). 곡이 재생 불가면 로드 때 제외. 무작위·DB 기록으로 세션 넘어 중복 회피. 고유명사는 읽는 법을 노트에.
- **유휴 타임아웃 180 s** 그대로.
- **백엔드 추론 low** (eea387a). none 에서 `end_conversation` 오발 — FINDINGS §4.
- **로그**: `DJ: model voice X.XXs after segment push`, `DJ: closing line heard, output quiet …s — playing <곡>`,
  `DJ: stopped without the closing line (…) — asking the backend`, `DJ check finished without a song (…)`,
  `DJ: check gave no song — return signal sent`, `DJ: listener spoke — no automatic song for this segment`,
  `Delegation created (…, by ray_dj_check_N)`.

## 가설

- **위임은 사용자 발화에 대한 응답으로만 생긴다.** 근거: 관찰된 대화 모델의 위임은 모두 사용자 발화 직후. 사용자 발화
  없는 조건(곡 소개 뒤, 앱 신호)은 전부 0. 반증: 사용자 발화 없이 대화 모델이 위임을 1회라도 만듦. (곡 재생은 앱이 맡아
  더 쫓지 않는다.)
- **위임을 요구하는 앱 지시는 무시된다.** 근거: 0/8, 지시에 든 말하기도 수행 안 함. 한계: 문구 1종, 채널은
  instructions.append 만. 반증: 다른 문구·채널(commentary 등)로 위임이 생김.
- **GPT-Live 기본 지시(비공개)가 위임을 사용자 요청에 묶는다.** 위 두 가설의 설명 후보. 직접 검증할 수단은 없다.
- **10-01 실기 17:45 오프닝 재시작은 시작 신호(instructions.append)가 말을 끊은 것.** 근거: 진입 순서 실험의 끊김 시점.
  반증: 시작 신호가 없는 지금도 오프닝 재시작이 나옴.
- **재작성 지시문이 진입 위임을 약하게 한다.** 근거: 재작성 계열 위임 누락 4/50(10-02~07 하네스), 8f0895a 0/6.
  반증: 같은 조건에서 8f0895a 도 비슷한 비율로 누락.
- **라이브 지시문의 `Backend tools` 목록이 백엔드 툴 선택을 돕는다.** 근거: 23/30 대 27~28/30, 유의하지 않음.
- **정지 뒤 "기억 안 남"은 노래 중 들은 곡 음원 때문이다.** 근거: 실기(원본 채널로 곡 36.9 s 입력)와 재현(입력 무음,
  8/8 기억)의 가장 큰 차이. 반증: 노래 중 곡 음원을 입력한 재현에서도 기억함.
- **처음 모른다고 답하면 그 답을 고수한다.** 근거: 실기 첫 질문이 모호("아까 했던 얘기 있잖아") → 되물음 → 다음 질문에서
  처음 "기억 안 남" 뒤 같은 답 반복. 재현은 처음부터 직접 물음. 반증: 실기 순서로 물어도 기억함.
- **모드 분리 지시가 DJ 때 일을 대화 밖으로 취급하게 한다.** 근거: 실기 1회. 재현 조건(기억함)에서는 변형 차이가 없어
  판단 불가. 반증: 증상이 재현되는 조건에서 모드 문장 제거·종료 신호 보강이 효과 없음.

## 열린 질문

- **끼어들기 분기**: 판정 조건(지금은 새 사용자 전사면 그 소재 감시를 끔 — 임시, 실기 소음·짧은 반응에 자주 걸릴 수
  있음), 끼어들기 뒤 자동 재생, 복귀 설계 재검토(구현을 더 신경 써서).
- **노래 정지 뒤 "기억 안 남"** (실기 1회, 재현 안 됨). 다음 재현 후보: 노래 중 곡 음원 입력, DJ 전 대화, 실기 질문 순서.
- **DJ 종료 뒤 할 수 없는 약속**: "다음 이야기로 넘어가볼게요" 뒤 아무것도 없음.
- **진입 실패**: 위임 누락·요청 못 들음 (10-06 자동 재생 실험 각 2/16).
- **판정 경로**: 공백 5~8 s, 엉뚱한 받는 말 2/7, 판정 메시지가 백엔드 입력에 세션 끝까지 쌓임(이후 요청 영향 미측정).

  15 s 무응답, 모델 자신의 `play_dj_song` 과 앱 재생의 겹침.

  (필요하면 DJ 중 assistant 전사는 저장 제외).
