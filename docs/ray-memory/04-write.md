# 메모리 Write

---

## 1. 기본 원칙

- 원문은 턴 전환 경계에서 DB에 즉시 저장
- 메모리 추출/갱신은 대화 중 수행하지 않고 세션 종료 후 비동기 배치 처리
  - Turn Shift 구조에서 대화 중 DB write가 섞이면 취소된 생성의 중복 처리 등 복잡성 발생
- 최근 몇 세션은 히스토리(블록 3)로 직접 전달되므로, 히스토리에서 밀려나는 시점에 write 처리

### 처리 흐름

```
세션이 히스토리에서 밀려남
  → 세션 원문을 LLM에 전달하여 추출:
      에피소드 리스트 (3인칭 내러티브 + importance)
      프로필 업데이트 (topic::sub_topic)
  → 에피소드 저장 (ADD)
  → 프로필 Merge (APPEND/UPDATE/ABORT)
  → 임베딩 생성 + 벡터 인덱스 갱신
  → 기억 인용 반영 (recency_decay 기준 일시 리프레시)
```

---

## 2. 에피소드 Write

### 추출

세션 원문을 입력으로, LLM이 0~N개의 에피소드를 추출한다.

- **형태**: 3인칭 내러티브. 맥락(상황, 감정)을 보존. 일시는 내러티브에 포함하지 않고 메타데이터로 분리
- **선별**: LLM이 판단. 사소한 세션은 0개 반환 가능
- 유저 발화에서만 추출 (어시스턴트 발화에서 fact를 뽑지 않도록 가드레일)
- 날짜 표현은 상대→절대 변환
- 세션 ID를 메타데이터로 저장 (원문 역추적용)

### 긴 세션 처리

세션 길이가 가변적이므로 윈도우 단위로 처리한다.

- 한번에 처리 가능한 양을 제한하고, 윈도우 간 겹침 구간을 두어 맥락 절단 방지
- 각 윈도우에서 개별 추출 후, 윈도우 간 중복 에피소드를 확인하여 병합

### Importance 판정

추출 시 LLM이 각 에피소드의 질적 중요도를 함께 판정한다.

- 감정적/개인적 의미가 있는 기억은 한 번만 언급되어도 높은 importance 부여
- Salience 공식에서 에피소드의 비맥락적 가치를 결정하는 유일한 요소

### 저장

- 새 에피소드는 항상 새 기억으로 저장 (ADD)
- 세션 간 같은 주제의 에피소드도 별도 저장 — 에피소드는 시간 맥락이 있는 사건 기록이므로 merge하지 않음

## 3. 프로필 Write

### Merge

Memobase의 APPEND/UPDATE/ABORT 패턴을 사용한다.

- 기존 슬롯 목록을 추출 프롬프트에 제공하여 같은 슬롯에 매핑 유도
- 배치 모드: 전체 슬롯을 한 번의 LLM 호출로 판정
- UUID를 정수 인덱스로 치환하여 LLM에 전달 (환각 방지)

### 프로필 스키마

친구 컨셉에 필요한 최소 슬롯으로 시작. 필요 시 확장.

```
# 시맨틱 프로필
basic_info::name, age, ...
interest::movie, music, book, ...
personality::성격 특성, 가치관, ...

# 관계 메모 (절차 기억)
interaction_style::tone, preference, ...
```

- 관계 메모는 시맨틱 프로필과 메커니즘 동일, 추출 지침만 별도 — 명시적 요청이나 확실한 선호 신호가 있을 때만 추출
- 불필요한 슬롯 (contact_info, demographics, education, work 등)은 제외

## 4. 확장 옵션

### 4-1. 검색용 키 포인트 추출

- 에피소드 저장 시 LLM이 검색용 핵심 문장(키 포인트)을 함께 추출
- 각 키 포인트마다 별도 임베딩 생성, 검색 시 매칭되면 부모 에피소드를 반환
- 에피소드 내러티브보다 작은 단위로 검색 표면적을 넓혀 검색 품질 향상

### 4-2. 시맨틱 메모리 도입

- 에피소드와 별도로 시맨틱 fact를 추출/관리하는 메모리 타입 추가
- 에피소드만으로 커버되지 않는 장기 축적 지식이 필요할 경우 도입 검토

### 4-3. 망각/정리

- importance 낮고 오래된 기억을 주기적으로 정리
- 저장 용량보다는 검색 noise 감소 목적
