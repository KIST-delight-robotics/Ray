# 메모리 Read

---

## 1. 에피소드 검색 파이프라인

```
쿼리 → 검색(병렬) → 랭킹 → 필터링 → 블록 6 주입
```

### 1-1. 쿼리 구성

현재 STT 텍스트 + 직전 N턴을 concat하여 쿼리로 사용한다. LLM 호출 없이 맥락을 보충하는 방식.

### 1-2. 검색

두 채널을 병렬로 실행하여 후보를 확보한다.

- **벡터 검색**: 임베딩 유사도 기반
- **BM25 검색**: SQLite FTS5 키워드 매칭

### 1-3. 랭킹

검색 결과를 두 단계로 순위 결정한다.

1. **RRF (Reciprocal Rank Fusion)**: 벡터/BM25 결과의 순위를 합산
2. **Salience**: RRF 점수를 기반으로 최종 점수 산출

```
salience = similarity × recency_decay × importance
```

| 요소 | 설명 |
|------|------|
| `similarity` | 검색 유사도 (RRF 합산 점수) |
| `recency_decay` | 시간 경과에 따른 감쇠. 마지막 갱신 또는 기억 인용 일자 기준 |
| `importance` | 질적 중요도 — Write 시 LLM이 판정 (감정적 강도, 개인적 의미 등) |

- recency_decay는 "최근에 들은 얘기를 더 잘 기억한다"는 인지적 자연스러움 반영. 지수 감쇠 사용: `exp(-ln(2) × days / half_life)`, 기본 half_life = 30일
- 기억 인용 시 감쇠 기준 일시를 현재로 리프레시. 기본 1회 인용 시 적용, 1회성 참조가 많을 경우 기준 상향 조정

### 1-4. 필터링

- **임계값 필터**: 최소 salience 미달 제외
- **메타데이터 필터**: 컨텍스트에 이미 표현된 세션 제외 — 현재 세션, 이월된 직전
  세션, 최근 세션 블록에 실제 포함된 세션 (02-session.md §3~4). 캡에서 탈락한
  세션은 제외하지 않아 검색으로 복귀 가능
- **Top-K**: 최대 개수 제한 → 블록 6에 주입

## 2. 기억 인용 (Memory Citation)

LLM 응답 끝에 현재 문맥에 관련된 기억의 ID를 출력하도록 프롬프트에서 지시한다. 이 신호를 **기억 인용**이라 한다.

### 블록 6 주입 포맷

기억은 정수 인덱스와 일시 메타데이터를 붙여 주입한다.

```
[M1] 사용자가 비 오는 날 인터스텔라를 보며 울었다고 함. (2026-03-15)
[M2] 사용자가 듄 2를 보고 전작보다 좋았다고 함. (2026-03-20)
```

### 인용 출력 포맷

응답 본문 끝에 관련된 기억의 인덱스를 출력한다. TTS 전에 파싱하여 제거.

```
Actually, I remember you saw Dune 2 recently...
[MEMORIES: M1, M2]
```

- "사용된" 기억이 아니라 "관련된" 기억을 출력 — 직접 인용하지 않았어도 맥락에 관여한 기억을 포함
- 인덱스는 턴마다 재할당되므로, 내부적으로 DB PK와의 매핑 테이블 관리 필요

### 용도

- **Retained Buffer**: 인용된 기억의 TTL 리셋 (§3)
- **recency_decay**: 인용된 에피소드의 감쇠 기준 일시 리프레시 (§1-3)

---

## 3. Retained Buffer

인용된 기억을 TTL 기반으로 보호하여, 대화 흐름이 바뀌어도 일정 턴 동안 블록 6에 유지하는 장치.

### TTL 관리

| 상태 | TTL 변동 |
|------|----------|
| 신규 검색 결과 진입 | TTL = 1 |
| 기억 인용됨 | TTL 리셋 (= N) |
| retained + 검색 hit + 미인용 | 유지 |
| retained + 검색 miss + 미인용 | -= 1 |
| TTL = 0 | eviction |

- 인용된 적 없는 기억(TTL = 1)은 다음 턴에 탈락하며, 검색에 다시 걸리면 재진입. 별도 보호 없음
- 인용된 기억만 retained buffer에서 TTL로 보호. 검색에 계속 걸리는 동안은 감쇠 정지, 검색에서도 빠지면 카운트다운 시작

### 블록 6 구성

```
매 턴 검색 시:
  1. retained 포함하여 검색 실행
  2. retained가 검색 결과에 포함 → TTL 유지
  3. 검색 결과에서 retained 제거 (중복 방지)
  4. 블록 6 = retained 기억 + 신규 검색 결과
```

- 토픽 전환 시 명시적 flush 없음 — 검색에 안 걸리기 시작하면 TTL 감쇠로 자연 퇴출
- retained overflow 시 TTL 기준으로 eviction (현재 쿼리 salience가 아닌 TTL 우선 — 토픽 전환 시 보호 유지)
- **슬롯 배분**: 블록 6 전체 슬롯 중 신규 검색 결과의 최소 보장 슬롯을 확보하고, 나머지를 retained에 할당 (초기값: 전체 10, 신규 최소 4)
- **초기 TTL 값(N)**: 인용된 기억이 보호되는 턴 수 (초기값: 3)

## 4. 프로필 Read

유저 프로필(블록 2)은 검색 없이 SQL 조회로 전체 로드한다. 슬롯 기반 구조이므로 토큰 크기가 예측 가능하며, 매 턴 항상 전체를 주입한다.

---

## 5. 확장 옵션

기본 파이프라인의 실제 성능을 확인한 후, 부족한 케이스에 맞춰 도입을 검토한다.

### 5-1. Temporal 검색

- dateparser(규칙 기반)로 쿼리에서 날짜 범위를 추출하여 해당 기간의 기억을 timestamp 기반으로 검색
- 벡터/BM25와는 별도 슬롯으로 주입 (RRF에 합산하지 않음)
- 범위 내 결과의 랭킹 기준, 별도 슬롯 배분은 미정

### 5-2. 그래프 확장

- SQLite edges 테이블로 fact 간 관계를 표현 (temporal/semantic 엣지, LLM 불필요)
- Read 시 검색된 fact의 1홉 이웃 점수를 부스트
- 간접 연결 검색이 필요해지면 도입

### 5-3. Cross-encoder 리랭크

- ms-marco-MiniLM-L-6-v2 (~22MB)로 RRF 후 후보 5~10개를 정밀 재평가
- 모델 추가 로딩 부담 vs 검색 정밀도 향상 트레이드오프

### 5-4. Learned Sparse Retrieval

- SPLADE 등 학습 기반 희소 검색으로 BM25를 대체 또는 보강
- 단순 키워드 매칭 대비 term expansion과 가중치 학습으로 검색 품질 향상 가능
- 모델 크기 및 Pi5 자원 제약 고려 필요

### 5-5. 프리페치 / 백그라운드 쿼리 생성

기본 파이프라인(STT + 직전 N턴)의 쿼리 품질이 부족한 경우를 대비한 옵션.

- **프리페치 키워드**: LLM 응답 끝에 다음 턴 관련 키워드를 출력하여 다음 검색에 활용. 추가 LLM 호출 없음.
- **별도 모델 백그라운드 생성**: 유휴 시간에 가벼운 모델로 정제된 쿼리 생성. Pi5 자원 제약 고려 필요.
- **Foresight 저장**: Write 시 미래 연상 텍스트를 별도 메모리로 저장하여 검색 대상에 포함. 빗나간 예측이 noise가 될 수 있어 유효기간/정리 기준 필요.
