# 세션 관리

---

## 1. 세션 정의

- wakeword로 시작, 종료 명령어 또는 일정 시간 무입력으로 종료
- 길이는 가변적 — 한두 마디부터 긴 대화까지

---

## 2. LLM 인풋 블록 구성

```
┌─────────────────────────────────────┐
│ 1. System Prompt (정적)             │  레이 성격, 지침
├─────────────────────────────────────┤
│ 2. User Profile (반정적)            │  프로필 슬롯 (세션 시작 시 전체 로드)
├─────────────────────────────────────┤
│ 3. Recent Sessions (준고정)         │  최근 세션 에피소드 (세션 단위, soft cap)
├─────────────────────────────────────┤
│ 4. Carryover (퇴거 전까지)          │  직전 세션 원문 + 세션 경계 마커
├─────────────────────────────────────┤
│ 5. Conversation (동적)              │  (롤링 요약) + 현재 세션 대화 턴 + 현재 발화
├─────────────────────────────────────┤
│ 6. Retrieved Memories (상시검색)    │  에피소드 기억 (Retained + 신규)
└─────────────────────────────────────┘
```

- 블록 1~4와 블록 5의 앞부분(기존 턴)은 같은 유저 턴 내 사전생성들 간 동일 → Prefix Caching으로 KV 캐시 재사용 가능
- 블록 5 끝(현재 발화)과 블록 6은 사전생성마다 달라지며, 맨 뒤에 배치하여 캐시 히트율 극대화
- 블록 3은 이월 퇴거 시 한 번 커진다 (§4) — 세션당 최대 1회의 캐시 무효화

---

## 3. 블록 3: 최근 세션 (Recent Sessions)

세션 종료 시 추출된 에피소드(04-write.md §2)가 이전 세션 표현과 요약의 역할을 겸한다. 별도 요약 LLM 호출은 하지 않는다.

```
[2026-03-27 14:00 session]
- User talked about watching Dune 2 over the weekend.

[2026-03-28 21:30 session]
- User said the Interstellar OST is their favorite.
```

- **세션 단위 선택·절단**: 최신 세션부터 통째로 채우고, soft cap을 넘기면 중단.
  최신 세션 1개는 캡과 무관하게 보장. 표시는 시간순(오래된 것 위).
- **직전 세션(N-1)은 이 블록에 넣지 않음**: 블록 4(이월)가 원문으로 담당.
  퇴거 시 에피소드로 강등되어 이 블록에 합류.
- **에피소드 없는 세션은 생략**: 추출 결과 0건(무의미 세션) 또는 추출 실패 세션.
  원문 폴백은 없음 — 추출이 정당하게 진행 중일 수 있는 유일한 세션(직전)은
  이월이 원문으로 커버한다.
- **검색 제외 불변식**: "블록에 있음 ⟺ 검색에서 제외". 실제 포함된 세션 + 현재
  세션 + 이월 세션만 검색 제외하고, 캡에서 탈락한 세션의 에피소드는 검색(블록 6)으로
  유입 가능.

---

## 4. 블록 4: 직전 세션 이월 (Carryover)

직전 1세션의 대화를 원문 그대로 새 세션 컨텍스트에 잇는다. 세션 간격과 무관하게
항상 이월하며, 간격 정보는 타임스탬프 마커로 전달한다.

```
[Previous session — 2026-03-28 21:30]
Earlier in that session: <직전 세션의 롤링 요약 (있으면)>
User: ...
Ray: ...
[New session — 2026-03-29 09:15]
```

- **재료는 전부 저장소에서 재조립**: 원문은 히스토리 백엔드(write-through)에 이미
  있고, 롤링 요약만 스왑 성공 시마다 영속화한다(최신 1세션분, `through_turn_id`
  포함 — 요약이 커버한 턴은 원문에서 제외). 크래시/재시작 후에도 이월이 동작한다.
- **퇴거(eviction)**: 히스토리 수요가 예산의 트리거 비율을 넘으면 이월분을 통째로
  제거하고 직전 세션의 에피소드를 블록 3에 추가한다 — LLM 호출 없음. 퇴거 후에도
  초과면 그때부터 현재 세션의 롤링 요약이 가동된다. 표현의 수명 주기:
  원문(직전 세션) → 에피소드(그 이전).
- **요약 혼합 금지**: 롤링 요약은 이월분이 남아 있는 동안 정지 — 직전 세션과 현재
  세션이 하나의 요약에 섞이지 않는다.
- **에피소드 미도착 시**: 퇴거를 보류하고 다음 build에서 재시도. 예산 초과분은
  oldest-drop 폴백이 이월 턴(가장 오래된 턴)부터 소거한다.

---

## 5. 블록 5: Conversation

현재 대화 턴들 + 현재 사용자 발화를 그대로 포함.

토큰 초과 시:
- 세션 내 롤링 요약이 오래된 턴을 접는다 (이월 퇴거 이후에만 가동)
- 요약 스왑 전 초과분은 역순으로 턴 단위 제거 (오래된 턴부터 탈락)

---

## 6. 세션 시작 시 처리

- 프로필 로드 (블록 2)
- 직전 세션 이월 로드 (블록 4) — 원문 + 영속화된 롤링 요약
- 최근 세션 에피소드 로드 (블록 3) — 이월 세션 제외, soft cap 적용
- Retained Buffer 리셋 — 세션 간 대화 맥락이 끊기므로 이전 세션의 retained 상태를 유지하지 않음

---

## 7. 세션 종료 시 처리

1. 메모리 Write 트리거 — 에피소드/프로필 추출 (비동기, 짧은 세션은 생략). 추출된 에피소드가 이전 세션 표현(블록 3)의 역할도 겸하므로 별도 요약 LLM 호출 불필요
2. 기억 인용 데이터 반영 — 세션 중 인용된 기억의 recency_decay 기준 일시를 현재로 갱신 (매 턴 실시간 처리)

롤링 요약은 종료 시점 처리가 아니라 세션 중 스왑 성공 시마다 이미 영속화되어 있다.
